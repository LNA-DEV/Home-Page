{{- /* Newsletter subscribe button. A
element, so the button itself needs no JS: the summary is the button, the Listmonk form is the panel it opens. The nine language-specific lists are a language x topic matrix, so the UI does not show nine checkboxes -- it shows a row of language pills and a row of topic bubbles, and ticks the intersection. Language-independent lists (data/newsletter.yaml -> standalone) join the topic row but are wired straight to their own checkbox, since no language applies to them. Progressive enhancement, because the pills are buttons and only JS can compute the intersection: the real checkboxes are rendered as a plain list and are what actually gets posted. assets/js/newsletter.js hides that list and reveals the pills. With JS off the visitor still gets a working, if plainer, form rather than an empty box -- which matters for the Tor build. That script is loaded by head.html, gated on `.HasShortcode "newsletter"`, so the class names and the data-lang / data-topic / data-list attributes below are its contract -- renaming one here breaks the picker silently into the plain-checkbox fallback. Pre-selection: English is checked in the markup so the no-JS form is useful; the script then adds the browser's own languages, which is the one thing a static build cannot know. `nonce` is the honeypot field from Listmonk's own generated form: it must stay empty (a filled one is treated as a bot). Keep it as Listmonk ships it. Checkboxes wrap their label instead of using id/for, so two newsletter shortcodes on one page cannot collide on duplicate ids. Usage: {{< newsletter >}} (optionally with title="..." / text="...") */ -}} {{- $data := site.Data.newsletter -}} {{- $topics := $data.topics -}} {{- $standalone := $data.standalone | default slice -}} {{- if not $data.languages -}} {{- errorf "newsletter shortcode: data/newsletter.yaml has no languages (%s)" .Position -}} {{- end -}}

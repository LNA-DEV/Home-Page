# Gaming

Games the user has played, modelled on the reading list, with **one page per game**. **Data**: `data/gaming.yaml` — a flat, unordered list, one entry per **copy** of a game (the same game on Switch and Steam is two entries), written by **multiple sources**. The `platform` field is the discriminator (`steam` | `epic` | `gog` | `switch` | `3ds` | `ds` | `playstation` | `manual` | …). Fields: `title`, `slug`, `platform` (all required), `appid` (Steam only — the **stable key** the Steam sync matches on) / `appName` (Epic + GOG — the stable key those syncs match on; for GOG it's the numeric product id), `playtimeMinutes`, `lastPlayed` (`"YYYY-MM-DD"`), `achievementsUnlocked` / `achievementsTotal`, `cover`, `link`, and the human-owned `extraMinutes` (hand-entered untracked/estimated minutes, **added to `playtimeMinutes`** in every UI total — folded in at the `gaming-merged.html` sum). **Covers**: committed JPEGs in `assets/images/games/covers/` named after the game title (`<Title>.jpg`, like book covers — `scripts/sync-steam.py` writes them that way), referenced as `images/games/covers/<file>` — in git, unlike gallery photos. **Rendered by** `layouts/shortcodes/gamingList.html` — a Steam-library-style cover grid at `/gaming/` with a stats header (game count, total hours, achievements), client-side sort (playtime / recently-played / A–Z), and a platform-filter row shown only when ≥2 distinct platforms are present; every card links to its game's page — plus `layouts/shortcodes/recentGaming.html`, a recently-played preview row on the About page mirroring `recentReading`, which links to the game pages too. `content/gaming/_index.{en,de,sv}.md` are **section** stubs (they were leaf bundles until the game pages needed children) whose body is `{{< gamingList >}}`, with `params.theme: gaming-home` — the branch in `layouts/_default/list.html` that renders the body and nothing else, since PaperMod's list would append every game page as a post entry — and `outputs: [HTML]`. Styles are `assets/css/extended/gamingList.css` + `recentGaming.css` + `gamePage.css` (auto-bundled, theme-variable-based so they work in light/dark); i18n lives under the `# Gaming` block in `i18n/{en,de,sv}.yaml`. Covers are resolved with `resources.Get .cover` + `image-variant.html` `fill 300x450` for uniform tiles (`/images/games/covers/fill-300x450/<Title>.<ext>`), with a title placeholder when a `cover` is absent. Not in the nav menu (reached via the About preview + the `/gaming/` URL), matching the reading list. **Hiding a game**: add its exact `title` to the `titles:` list in `data/gamingIgnore.yaml` (case-insensitive, whitespace-trimmed) — the entry stays in `data/gaming.yaml` and keeps syncing, but is dropped from every view, its page included. The filter lives at the shared choke point `layouts/partials/gaming-merged.html` (used by `gamingList`, `recentGaming` and the page adapter), so it applies to the grid, the stats header, the About-page recent row and the pages alike.

**The slug is a game's identity** (`docs/concepts/gaming-game-pages.md` §2). Copies that share a `slug` are one game: one card, one page at `/<lang>/gaming/<slug>/`. `gaming-merged.html` groups on it — not on the title, which stores disagree about (`Rocket League®` on Epic, `Rocket League` on the Switch are one game). A sync writes a copy's slug **once**, the first time it sees the game (`scripts/gaming_common.py`: `™®©` stripped, `ß`→`ss`, ASCII-folded like the gallery's English `.fileSlug`), emits it as the entry's **second line**, and never recomputes it — a Steam rename moves neither the card nor the URL. A new copy whose slug another platform already uses **joins** that game (printed in `--dry-run`); a second game of the *same* platform with the same title gets the key appended. Hand-added entries need the slug typed. `gaming-merged.html` stops the build on a copy without a slug, a malformed one, two copies of **one platform** under one slug (two different games merged by accident), and a `rating`/`notes`/`genres`/`tags` line on a copy — those moved to `data/gamePages.yaml`. `scripts/gaming-add-slugs.py` was the one-time migration (**done**; a rerun is a no-op). A merged game's title is `gamePages.yaml`'s `title` if set, else the first copy in the fixed order hand-added → steam → gog → epic (not file order: each sync moves its block to the bottom).

**Four data files, one owner each:** `data/gaming.yaml` (the copies — syncs + hand), `data/gamePages.yaml` (per **game**, keyed by slug, **only ever written by a person**: own `description` string-or-`{en,de,sv}`, `rating`, `notes`, a `wikidata:` pin or `none`, a `steam_appid` pin, `slugAliases`, a `title` override — an unknown slug, a duplicate record, an out-of-range rating or an alias that is a live slug is a build error), `data/gameFacts/<slug>.json` (written by `scripts/game-enrich.py`), `data/gameAchievements/<platform>-<id>.json` (written by the Steam and GOG syncs). The machine files are deterministic JSON (`gaming_common.dump_json`: sorted keys, written only when the bytes change).

**Game pages** come from content adapters, `content/gaming/_content.{en,de,sv}.gotmpl` → `layouts/partials/game-pages.html` (one per language, `translationKey` top-level, slug language-neutral, `slugAliases` → absolute `/gaming/<old>/` aliases). Theme `game`, dispatched in **both** `page.html` and `single.html` to `layouts/partials/game-detail.html`: breadcrumb; cover, platforms, rating, a facts row (genre · game mode · developer · publisher · year, via `game-facts.html`) and one store link per copy; playtime with a per-platform breakdown; the description with its credit; the owner's notes; screenshots; one achievement block per copy that has a file (`game-achievements.html`). Every section renders only when it has content. **The description** is a priority chain in `layouts/partials/game-description.html`, language before source, English last: `own(L) → wikipedia(L) → steam(L) → own(en) → wikipedia(en) → steam(en)`. Every candidate is stored, so the order is one `slice` in that partial and changing it needs no refetch. The credit travels with the text (an English fallback credits the English article): Wikipedia reuses the dex's `dex_source_wikipedia` line (CC BY-SA, abridged), Steam's store blurb — publisher copy with no licence — gets `game_source_steam`, own text none. **Indexing**: the pages set `robotsNoIndex`, so `layouts/partials/robots-indexable.html` — the one predicate behind both the meta robots and `sitemap.xml` (`docs/concepts/tag-pages.md` §2) — keeps them out of the index and the sitemap. They also set `robotsFollow`, which `head.html` turns into `noindex, follow` the way it does for taxonomy pages (`robotsNoIndex` alone means `noindex, nofollow`). And they set the top-level AddPage key `sitemap: {disable: true}`, which `sitemap.xml` now honours too (`where .Data.Pages "Sitemap.Disable" "!=" true` — Hugo's built-in sitemap does, this override of it never did). They stay in the site search. `$indexable` in `game-pages.html` is the one switch. `/gaming/` itself, now a section and so not in `site.RegularPages`, is added to `layouts/_default/index.json` by hand, like `/travel`. Structured data: a `WebPage` about a `VideoGame` (name, genre, gamePlatform, Wikidata `sameAs`), no author, no date. Link previews keep the site logo: a cover is publisher art under no licence.

**Achievements**: `sync-steam.py` asks, per game with achievements, `GetPlayerAchievements` (authoritative for which achievements exist and which are unlocked, so the page's row count always equals the card's `achievementsTotal`), `GetSchemaForGame` in english/german/swedish (names, descriptions, icon, `hidden`), and the public `GetGlobalAchievementPercentagesForApp` — 5 requests a game, ~2½ minutes a full sync. A language that only repeats English is dropped (Steam's silent fallback). `unlocked` is RFC 3339 in **Europe/Berlin with its offset** — fixed zone, so deterministic, and Hugo's `time.Format` keeps the offset, so an unlock at 00:14 local time is dated that day. **Steam delivers no description for a hidden achievement at all**, locked or unlocked (0 of 660, checked 2026-09-28); the row says so. Icons are downloaded once (named as the store names them — a content hash for most Steam games) into `static/images/games/achievements/<platform>/<id>/` and **committed** (~23 MB, 3,100 files); a locked icon is the unlocked one greyed by CSS. **Static, not `assets/`, on purpose**: every file fetched with `resources.Get`/`resources.Match` goes through one LRU partition of Hugo's in-memory cache that is capped by **count** — about 4,000 entries (dynacache: 100,000 / 10 × weight 0.4); `HUGO_MEMORYLIMIT` does not change it. An evicted resource is re-created on its next use and published a second time. That is **harmless in itself**: the cache is the build process's memory (not `resources/_gen/`, which only holds *processed* output and is untouched by this), and the second write is byte-identical, same source, same path. But `--printPathWarnings` counts writes per target and reports `Duplicate target paths` — meant for two *different* sources colliding, here a false positive — and `deploy.sh` builds with `--panicOnWarning`, so the deploy stops at the `hugo` step. The site already sends ~1,200 files through it (650 gallery photos, 156 game covers, 153 dex data files, 108 dex images, 69 book covers, CSS/JS); the ~3,100 icons pushed it over, and the warning named all 150 dex range files plus a varying handful of icons. Measured on 2026-09-28: clean at 3,104 extra icons, broken at 3,145, clean again with all icons but an empty gallery mount. **This is a site-wide ceiling, not an icon quirk** — and since the stable image names every processed image is a copied resource too (~4,250 more), so the site is past it on its own and the warning comes back intermittently; see *Processed images* in `docs/gallery/images.md`. `static/` is a **workaround**; the open task `docs/concepts/duplicate-target-paths.md` replaces it with a classifier for that warning and moves the icons back to `assets/`. The template checks `fileExists "static/…"` before emitting an `<img>`. 33 icons of three games are gone from every Steam CDN host, grey variant included — those rows show an empty tile. A game whose achievements were not fetched (`--no-achievements`, a transient failure) keeps its old counts **and** its file, so card and page keep agreeing. GOG: `sync-gog.py` writes its file from the response it already fetched; its documented response has no percentage (`rarity` is taken if present). Epic has no achievement API; Nintendo has no achievements. The list's filter (all / unlocked / locked) and sort (default / rarest first / A–Z) are `assets/js/game-achievements.js`; the controls render `hidden` so no-JS visitors get no dead buttons.

**Facts — `scripts/game-enrich.py`** (on demand, stdlib only; workflow below). Wikidata item: the `gamePages.yaml` pin, else the item whose `P1733` is the Steam copy's appid (one SPARQL query; if that item is an **edition** without articles, its `P629` "edition of"); **a title match is never written** — `--propose` prints candidates to check and pin, because a title search finds convincing wrong hits. Wikipedia: each language's own article, abridged by the dex's rule, which now lives in `scripts/wiki_common.py` shared with `dex-enrich.py`. Steam store `short_description` ×3 languages. Facts: `P136` genre and `P404` game mode (en/de/sv labels), `P178` developer, `P123` publisher, earliest `P577`. The file is overwritten whole per game.

**Screenshots**: a machine-local mount in the gitignored `config/_default/module.yaml` (see `module.yaml.example`) to `assets/images/games/screenshots/`, **one folder per game slug**, files sorted by name. `layouts/partials/game-screenshots-list.html` finds them; the page renders `fit 640x640 jpg` thumbnails and `fit 1920x1920 jpg` large variants through `image-variant.html` (JPEG, never upscaled, in `fit-640x640-jpg/` and `fit-1920x1920-jpg/` beside the game's folder) into a PhotoSwipe strip (`assets/js/game-screenshots.js` — not `lightbox.js`, which is the gallery's). The original is never referenced, so never published, and Hugo's variants carry no metadata; `gallery-embed-metadata.py` never sees these. PhotoSwipe's JS and CSS load only on a page that has screenshots. A folder named after no page is a `warnf` (`game-screenshot-check.html`, once per build); a missing or empty store is not.

## Game pages: facts, descriptions, screenshots

Every game on `/gaming/` has a page at `/<lang>/gaming/<slug>/`. Design:
`docs/concepts/gaming-game-pages.md`; the data model:
above. What a person writes goes in **`data/gamePages.yaml`**, keyed by
slug — see its header for every field. Nothing else is typed by hand.

### `scripts/game-enrich.py` — genres, developer, Wikipedia and store text

Writes `data/gameFacts/<slug>.json`, nothing else. Stdlib only, never runs git.

```
python3 scripts/game-enrich.py --dry-run     # what it would fetch
python3 scripts/game-enrich.py               # all games, ~8 minutes (store rate limit)
python3 scripts/game-enrich.py --missing     # only games without a facts file
python3 scripts/game-enrich.py --only stardew-valley
```

- **Steam games resolve on their own** — Wikidata knows their Steam app id. So
  a Steam game is enriched with no help.
- **Everything else needs a Wikidata pin.** Switch, 3DS, DS, Epic and GOG
  copies have no id Wikidata can be asked about, and a title search finds
  convincing wrong hits, so the script **never** writes one. Run
  `python3 scripts/game-enrich.py --propose`: it prints, per game without an
  item, the video-game items whose label matches — first one uncommented,
  alternatives commented out, `[exact]` / `[check]` marks. Check each against
  the game (year, platform), paste the right ones into `data/gamePages.yaml`
  (`wikidata: Q…`, or `wikidata: none` for a game Wikidata does not have, so it
  stops being proposed), then `--missing`.
- **A game not owned on Steam** still gets the Steam store blurb when its item
  carries a Steam app id; `steam_appid:` in `gamePages.yaml` pins one by hand.
- **The description shown** is the first of: your own text, Wikipedia, the
  Steam store — in the page's language first, then English. Your own text goes in
  `gamePages.yaml` `description:` (a string for English, or `{en, de, sv}`).
- The facts file is **overwritten** per game on every run; never edit it.
  Rerun after pinning, or when Wikipedia has changed; nothing needs it to run
  regularly.

### Screenshots

A machine-local folder, mounted like the gallery's photo store: add the
commented screenshot lines from `config/_default/module.yaml.example` to your
`config/_default/module.yaml` with your folder as `source` (a real directory,
not a symlink). Inside it, **one folder per game slug** —
`stardew-valley/2024-03-01_12-00-00.png` — and the files are shown in name
order. Steam keeps screenshots under
`~/.local/share/Steam/userdata/<id>/760/remote/<appid>/screenshots/`; copy
rather than mount those, since Steam's folder names are app ids, not slugs.
Only resized JPEG variants are published — never the original — and a folder
that matches no game is a build warning (so a stopped deploy). Rebuilding
generates the variants once; they are cached like every other image.

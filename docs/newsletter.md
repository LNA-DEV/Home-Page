# Newsletter

Self-hosted listmonk (`listmonk.lna-dev.net`, `../Web-Services/listmonk/`). One form, `layouts/partials/newsletter-form.html`, in three placements: the header CTA's dialog (`newsletter-cta.html`), the post-footer card (`newsletter-in-footer.html`) and the `{{< newsletter >}}` shortcode. Lists and endpoints are in `data/newsletter.yaml`, and `assets/js/newsletter.js` drives the form.

- **The form posts to `/subscription/form`, never to `/api/public/subscription`.** listmonk (v6.2.0) checks the captcha and the `nonce` honeypot on the form endpoint only. The API takes a signup without either, so posting there would make the captcha decorative, and Caddy closes that route once ALTCHA is on.
- **The honeypot is listmonk's `nonce` field, and it is a text field on purpose.** listmonk answers a form post with a non-empty `nonce` with 502, before it looks at the captcha. Its generated form makes the field `type="hidden"`, which a form-filling bot leaves alone, so as shipped it caught nothing. Here it is a text input moved off-screen by `.newsletter-hp` (`tabindex="-1"`, `autocomplete="off"`, in an `aria-hidden` wrapper), and `newsletter.js` posts it whatever it holds: listmonk judges it, not the script. Never `type="hidden"` or `display: none` again. The name has to stay `nonce`.
- **The captcha is ALTCHA, a proof of work, and nobody sees it.** `newsletter.js` fetches the challenge from `/api/public/captcha/altcha` when the form first gets focus, solves it with `crypto.subtle` (about a second at listmonk's default of 300,000) and sends the solution as `altcha`. A 404 for the challenge means ALTCHA is off in listmonk, and the form then posts without a solution. That lets the site deploy before the captcha is switched on, and keeps the form working if it is ever switched off. Never hCaptcha: it is a third party, which the maps rule out for the same reason.
- **Signing up needs JavaScript, deliberately.** `head.html` puts `js` on `<html>` with an inline script before first paint, and `newsletter.css` hides every placement without it. There used to be a working no-JS form (the Tor build's path); it was given up for the captcha.
- **`#newsletter` opens the header dialog on any page**, and closing it takes the hash off again. The root page keeps query and hash on its jump to a language home, so `https://lna-dev.net/?ref=github#newsletter` (the GitHub profile README) lands on the visitor's language with the form open. Such an open and its signup report `source: "link"` to Plausible instead of `"header"`. Give an outside link `?ref=`: after the root page's jump the referrer is lna-dev.net itself, so without it the visit counts as direct.
- CORS: listmonk sends `Access-Control-Allow-Origin` for every origin under Settings → Security → Trusted URLs. Both requests are simple CORS requests (a GET, and a form-encoded POST), so there is no preflight.
- Tests: `tests/e2e/newsletter.spec.ts` against `mockListmonk` in `tests/support/network.ts`, which serves a solvable challenge or the 404, and answers a filled honeypot with 502 the way listmonk does.
